# User portal C0 (Foundation) + C1 (Studio, recordings, library, admin)

Source of truth: [brainstorm report](../reports/brainstorm-261102-0735-user-portal-postgres-rewrite.md) plus the user's answers of 2026-11-02 (admin in C1, account rules win dictionary ties, quota defaults, fail-closed moderation, `<en>` fallback). Specs: `docs/vieneu_tts_docs_specs/docs/specs/` (master, 01, 02, 04, 07, 08, 09). Specs define no admin screens; phases 13-14 design them. Spec conflicts are resolved in the table below.

## Architecture

```text
Browser (Next.js static export, same origin) --cookie+CSRF--> portal: FastAPI /api/v1 (+ /api/v1/admin, role-guarded)
portal --SQLAlchemy 2--> Postgres (Alembic)        portal --boto3--> S3 (MinIO dev, any S3 prod, 15-min signed URLs)
portal --httpx + service key--> engine: apps/openai_speech.py (/v1/audio/speech stream, /internal/v1/render, /v1/voices)
worker (python -m vieneu_portal worker) --> same DB/S3/engine; claims ASYNC PENDING recordings (SKIP LOCKED, leased)
Text path: original_text -> moderation -> math/chem normalize (dictionary sources protected) -> [account + system rules + English fallback, one pass] -> moderation of processed text -> length cap -> engine
```

- Schema = spec 08 DDL plus documented additions (auth/sessions, auth throttle, roles `USER/ADMIN/SUPERADMIN`, per-user synthesis lease, recording render queue columns, system dictionary layer with `rule_kind` and `term_key`, legacy provenance ids, object keys, daily-reset date, `admin_audit_log`). No generic jobs table in C1: the recording row is the queue item.
- Characters = code points of NFC original text, identical in Python and TS; tokens = `ceil(chars * rate_milli / 1000)`. Defaults (env-configurable): 150 000 tokens, 50 000 chars/day, 1 token/char, 14-day trial.
- Charge after success via conditional `UPDATE` in the transaction that records success. Moderation reject, moderation outage (503, fail-closed), engine/storage failure and lost races charge nothing. Stream charges only on completion. Admin token adjustments are the only other counter writer, always audited.
- One in-flight synthesis per user (stream, sync generate or queued async generate), held by a leased `users.synthesis_lock_until`. With one request in flight the read-only precheck is exact, so parallel streams or queued jobs cannot overspend, and one account cannot occupy every engine slot. A second request gets `409 SYNTHESIS_IN_PROGRESS`.
- Processed text: billed on the original (spec), but `processed_text` must be at most `ENGINE_MAX_INPUT_CHARS` and at most `max(2 x chars, chars + 2000)`; otherwise `422 TEXT_TOO_LONG_AFTER_PROCESSING`. Sync/async routing uses processed length. Moderation runs on the original and again on the processed text, and dictionary targets are moderated when saved, so a rule cannot smuggle blocked content.
- Dictionary: longest match first over the combined set; equal-length ties: account rule > system replace rule > English fallback, then list order. Protected spans (`[...]`, `<en>...</en>`, `<|...|>`) never rewritten. Tokens that are enabled dictionary sources are never rewritten by the math/chem normalizer (so `B2B`, `F0` keep their seed rules).
- `<en>` interpretation (confirmed): an English term that matches any dictionary rule uses that rule's replacement; otherwise known English terms (fallback list) are wrapped in `<en>...</en>` for the engine's English handling; unknown words are left to the engine.
- Audit log kept forever (no purge job in C1); every admin mutation and every admin listing of another user's recordings (`user.recordings_view`) writes one row.
- Admin parity: web user management (phases 13-14) with last-active-superadmin and self-demotion guards; only SUPERADMIN may create or change ADMIN/SUPERADMIN accounts. Users change their own password. Script Lab replaced by `python -m vieneu_portal text preview` (same pipeline and rules as the portal).
- Engine security: the engine refuses to start on a non-loopback bind without `VIENEU_API_KEY`; compose files require the key (`${VAR:?}`); the portal stack never publishes the engine port.
- Breaking changes (documented in phase 15): from phase 6 the engine accepts only `VIENEU_API_KEY`; migrated DB keys are stored but not usable until the C2 developer API; global dictionaries apply only through the portal.
- Packaging: the portal image installs the PEP 735 dependency group `portal` plus `pip install --no-deps .`; it never imports `vieneu` and contains no onnxruntime/torch (image check).
- Deferred UI shown as disabled "coming soon": background music, onboarding checklist expansion (progress from existing onboarding fields), support chat. No email verification or reset-by-email.
